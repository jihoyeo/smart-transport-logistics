## 짚을 것 (서머리.md 3장에서 고른 것)

- 3.6: A*는 확정 노드를 1.7배 줄이는데 실행 시간은 더 길다(7.4ms → 9.8ms). 파이썬에서 하버사인 계산이 힙 연산보다 비싸다. 바꿀 때마다 재 본다.

## 막히기 쉬운 지점 (수요일 시연용)

1. 도착 노드를 힙에 **넣을 때** 끝내면 틀린다. 꺼냈을 때 끝낸다. 6노드 그래프에서 이 차이가 드러나는 예를 칠판에 그린다.
2. 같은 노드가 힙에 여러 번 들어간다. `done` 집합으로 걸러야 한다. 안 걸러도 답은 같지만 확정 노드 수가 달라져 B3 해석이 어긋난다.
3. astar는 힙에 `(우선순위, 실제 거리, 노드)` 셋을 넣고 꺼낼 때 실제 거리를 쓴다. 우선순위를 거리로 쓰면 NetworkX와 어긋난다.
