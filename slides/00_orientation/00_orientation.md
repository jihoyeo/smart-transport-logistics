# 이 과목

## 이 과목에서 만드는 것

- 결과물: 도시 모빌리티 시뮬레이터 한 대 — 12주간 밑바닥부터
  - 도로망 → 최단경로 → 환승 경로 → 수요 생성 → 배차 → 지표·시각화
- 마지막 적용 대상: 가천대 교내셔틀 무당이의 개선안 분석
- 데이터 분석·최적화·머신러닝은 별도 단원 없음
  - 시뮬레이터를 만들다 필요해진 지점에서 하나씩

> 과목 이름은 스마트 교통물류지만, 개론 수업이 아닙니다. 결과물이 하나 있는 수업입니다. 학기가 끝나면 여러분 손에 시뮬레이터 한 대가 남습니다. 이론을 먼저 다 배우고 나중에 적용하는 순서가 아니라, 만들다가 막히는 지점에서 그때 필요한 이론을 다루는 순서입니다.

## 시뮬레이터의 네 부분

![도로망·경로 탐색·수요·배차로 이루어진 시뮬레이터](figures/ch01_framework.png)

> 이 그림이 학기 전체의 진도표입니다. 도로망(2~4주차), 경로 탐색(3·5·6주차), 수요(7주차), 배차와 루프(10~11주차). 매주 이 그림의 상자 하나를 채웁니다.

## 학습 목표

이 과목을 마치면 다음을 할 수 있습니다.

- OpenStreetMap 도로망과 GTFS 시간표를 분석 가능한 형태로 정리
- 최단경로(다익스트라·A*)와 RAPTOR 직접 구현, 실제 엔진과 대조 검증
- 통행 수요 생성, 배차 알고리즘 비교, 이산시간 시뮬레이션 루프 작성
- 개선 시나리오 설계와 서비스율·대기시간 기반 효과 제시

## 직접 짜는 것과 가져다 쓰는 것

- 직접 작성 3개 — 라이브러리 없이
  - 최단경로 3주차 약 90줄 · RAPTOR 5주차 약 150줄 · 루프 11주차 약 150줄
- 읽고 실험 — 수요 생성기, 배차 알고리즘
  - 완성된 코드에서 인자만 변경
- 엔진 위임 — 무거운 계산은 DTUMOS에 HTTP 호출
  - 엔진 내부는 Rust, 이 과목의 범위 밖

> 전부 직접 짜면 12주 안에 시뮬레이터가 완성되지 않습니다. 짧은 세 개만 직접 짜고, 나머지는 읽고 실험합니다. 직접 짠 코드는 항상 기준과 대조합니다 — 다익스트라는 NetworkX와, RAPTOR는 실제 엔진과.

## 수업 방식

- 화요일 개념·코드, 수요일 직접 작성과 실행 — 노트북 매 시간 지참
- 수업 중 LLM 사용 — ChatGPT·Claude·Gemini 구독 권장
  - 조건: 나온 코드를 이해하고 막힌 곳을 고칠 수 있을 것 (코딩테스트에서도 사용 가능)
- "돌아간다"와 "맞다"의 구분 — 직접 짠 코드는 항상 기준과 대조
  - 이 습관이 이 과목에서 가장 오래 남는 것

> LLM 금지가 아니라 권장입니다. 다만 LLM이 짠 코드를 설명하지 못하면 시험에서 그대로 드러납니다. 대조 습관 — 무엇과 비교했고 어디가 달랐는지 — 이 과목이 기르려는 태도입니다.

## 중간시험

- 일시 10-27(화) · 범위 교재 0~8장과 12장
- 구성: 단답형 closed-book 40% + 코딩테스트 open-book 60%
  - 코딩테스트는 사이버캠퍼스 출제, ipynb와 데이터 제공, LLM 사용 가능
- 출제 방향: 암기가 아니라 주어진 데이터에서 답을 뽑아내는 과정

> 학사일정상 중간고사 기간은 10-20~26이지만 8주차 휴강으로 1주 순연했습니다. 코딩테스트에서 LLM 사용을 허용하는 이유는 실무에서도 사용하기 때문입니다. 대신 문제가 "LLM에 그대로 넣으면 풀리는" 형태가 아닙니다.

## 기말 팀 프로젝트 — 무당이

- 대상: 가천대 교내셔틀 무당이 — 개선 시나리오 효과를 수치로 제시
  - 4~5명 팀, 최대 6팀 · 6주차 시작, 12주차 발표
- 출발 조건: GTFS 없음, 승하차 기록 없음 → 둘 다 직접 작성·조사
- 분담: 팀은 현황 재현, 팀원 각자 개선 시나리오 1개
  - 배차간격 · 노선 변경 · 차량 대수 · DRT 대체 · 시간대별 운행 중 택 1 (팀 내 중복 불가)

> 매일 타는 셔틀이 대상입니다. 데이터가 없는 상태에서 시작한다는 점이 이 프로젝트의 요점입니다. 시간표를 GTFS로 옮기고 승하차를 세어 보면, 교통 데이터가 어떻게 만들어지는지 알게 됩니다. 조사는 8주차 휴강 주에 캠퍼스에서 합니다.

표: 기말 프로젝트 산출물 일정

## 과제

- HW1 (4주차) — 교재 2장 도로망 통계와 3장 다익스트라 구현
- HW2 (6주차) — 직접 짠 RAPTOR를 참조 결과와 대조하고 차이 설명
- HW3 (9주차) — 무당이 GTFS 작성·검증과 승하차 조사표 · 팀 제출, 8주차 휴강 대체
- 세 과제 공통 산출물: 돌아가는 코드가 아니라 기준과 대조한 결과

> 무엇과 비교했고 어디가 달랐는지를 쓰는 것이 과제에서 실제로 채점하는 부분입니다. 코드가 돌아가기만 하면 되는 과제는 없습니다.

# 실습 환경

## 환경 설치

- Python 3.11
- 저장소 복제 후 의존성 설치
  - requirements.txt가 버전 고정 → 교재와 같은 그림
- 확인: import 한 줄

```bash
git clone \
  https://github.com/jihoyeo/mobility-simulation-book.git
cd mobility-simulation-book
pip install -r requirements.txt

python -c "from smartmob import Dtumos"
# (결과) 아무 출력 없이 끝나면 설치 성공
```

> requirements.txt가 버전을 전부 고정해 두었으므로, 같은 버전이면 교재와 같은 그림이 나옵니다. 수요일 수업 전까지 이 네 줄이 되는 상태로 와야 합니다. 막히면 단톡방에 올리세요.
