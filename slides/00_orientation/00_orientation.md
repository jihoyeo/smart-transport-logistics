# 수업 소개

## 한 학기 동안 만들 시뮬레이터

- 한 학기 결과물: 도시 모빌리티 시뮬레이터
  - 도로망 → 최단경로 → 환승 경로 → 수요 생성 → 배차 → 지표·시각화
- 기말 적용 대상: 가천대 교내셔틀 무당이의 개선안 분석
- 데이터 분석·최적화·머신러닝: 구현 과정에 필요한 시점마다 적용

> 스마트 교통물류 전반을 훑는 개론 수업은 아닙니다. 한 학기 동안 하나의 시뮬레이터를 단계별로 완성합니다. 이론을 모두 배운 뒤 적용하는 방식이 아니라, 구현 단계마다 필요한 이론을 배우고 바로 적용합니다.

## 시뮬레이터의 전체 구조

![도로망·경로 탐색·수요·배차로 이루어진 시뮬레이터](figures/ch01_framework.png)

> 이 그림은 한 학기 동안 다룰 범위를 보여 줍니다. 2~4주차에는 도로망, 3·5·6주차에는 경로 탐색, 7주차에는 수요, 10~11주차에는 배차와 시뮬레이션 루프를 다룹니다.

## 학습 성과

- OpenStreetMap 도로망과 GTFS 시간표를 분석 가능한 형태로 정리
- 최단경로(다익스트라·A*)와 RAPTOR 직접 구현, 실제 엔진과 대조 검증
- 통행 수요 생성, 배차 알고리즘 비교, 이산시간 시뮬레이션 루프 작성
- 개선 시나리오 설계와 서비스율·대기시간 기반 효과 제시

## 직접 구현과 기존 도구 활용

- 직접 구현: 라이브러리 없이 알고리즘 3개 작성
  - 최단경로 3주차 약 90줄 · RAPTOR 5주차 약 150줄 · 루프 11주차 약 150줄
- 제공 코드 활용: 수요 생성기와 배차 알고리즘
  - 완성된 코드에서 인자만 변경
- 외부 엔진 활용: 계산량이 큰 작업은 DTUMOS에 HTTP 요청
  - 엔진 내부는 Rust, 이 과목의 범위 밖

> 모든 기능을 직접 구현하지는 않습니다. 학습 목표와 직접 관련된 알고리즘 세 개는 직접 작성하고, 나머지는 제공 코드나 외부 엔진을 활용합니다. 직접 구현한 결과는 기준 구현과 대조합니다. 다익스트라는 NetworkX, RAPTOR는 DTUMOS 결과와 비교합니다.

## 중간시험

- 일시·범위: 10-27(화) · 교재 0~8장과 12장
- 구성: 단답형 closed-book 40% · 코딩테스트 open-book 60%
  - 사이버캠퍼스에서 출제 · ipynb와 데이터 제공 · LLM 사용 가능
- 평가 내용: 주어진 데이터를 분석해 답을 도출하는 과정

> 학사일정상 중간고사 기간은 10월 20일부터 26일까지지만, 8주차 휴강으로 시험을 한 주 늦췄습니다. 코딩테스트에서는 실무 환경을 고려해 LLM 사용을 허용합니다. 단순히 문제를 입력해 답을 얻는 방식이 아니라, 제공된 데이터를 분석하고 결과를 검증하는 과정을 평가합니다.

## 기말 팀 프로젝트: 무당이

- 대상: 가천대 교내셔틀 무당이 — 개선 시나리오의 효과를 수치로 비교
  - 4~5명 팀, 최대 6팀 · 6주차 시작, 12주차 발표
- 시작 조건: GTFS와 승하차 기록 없음 → 시간표 작성과 현장 조사부터 진행
- 역할 분담: 팀 단위 현황 재현 · 개인별 개선 시나리오 1개
  - 배차간격 · 노선 변경 · 차량 대수 · DRT 대체 · 시간대별 운행 중 택 1 (팀 내 중복 불가)

> 학생들이 매일 이용하는 셔틀을 분석 대상으로 삼습니다. 기존 GTFS와 승하차 기록이 없기 때문에 시간표를 직접 옮기고 현장에서 승하차 인원을 조사합니다. 이 과정을 통해 교통 데이터가 만들어지는 절차도 함께 익힙니다. 현장 조사는 8주차 휴강 기간에 교내에서 진행합니다.

# 실습 환경

## 실습 환경 설치

- Python 3.11
- 저장소 복제 후 의존성 설치
  - requirements.txt가 버전 고정 → 교재와 같은 그림
- 설치 확인: import 한 줄

```bash
git clone \
  https://github.com/jihoyeo/mobility-simulation-book.git
cd mobility-simulation-book
pip install -r requirements.txt

python -c "from smartmob import Dtumos"
# (결과) 아무 출력 없이 끝나면 설치 성공
```

> requirements.txt에는 패키지 버전이 고정되어 있어 같은 환경에서 교재와 같은 결과를 재현할 수 있습니다. 수요일 수업 전까지 명령을 모두 실행하고 import가 오류 없이 끝나는지 확인해 주세요. 설치 중 문제가 생기면 단톡방에 오류 메시지를 올리면 됩니다.

## 실행 환경 선택

- 기본 환경: 강의용 공용 서버
  - 서버 연결 없이도 교재의 녹화 결과로 코드 실행 가능
- 엔진 내부 확인: 개인 노트북의 Docker와 사전 빌드 이미지 사용
- Google Colab: 각 장의 Colab 배지 → 첫 셀에서 smartmob.colab.bootstrap()

> 계산량이 큰 작업은 공용 서버에서 실행하므로 개인 노트북의 성능은 실습 진행에 큰 영향을 주지 않습니다. 서버에 연결할 수 없는 경우에는 교재에 저장된 실행 결과를 사용합니다.
