# 교재 1.1 모빌리티 평가 관점

## 관점별 평가 기준

표: 세 관점이 바라는 것과 그것을 측정하는 지표
| 관점 | 바라는 것 | 지표 |
|---|---|---|
| 승객 | 짧은 대기·통행시간 | 대기시간, 통행시간 |
| 운영자 | 운행 효율 향상 | 차량당 승객 수, 가동률 |

- 관점 간 충돌: 증차 → 대기시간 감소, 빈 차량 증가
- 비교 예시: 차량 10대 증차 전후의 대기시간과 빈 차량 수

# 교재 1.2 시뮬레이션이 필요한 이유

## 실제 운영 자료의 한계

- 버스 20대의 한 달 운행 기록 → 선택한 배치와 배차 규칙의 결과 한 가지
- 그 기록으로 답하기 어려운 질문
  - 10대였을 때의 대기시간
  - 차고지 2곳 분산 배치
- 대안 비교에 필요한 조건: 같은 기간을 운영 조건만 바꿔 반복 관찰
- 시뮬레이션: 실제 반복 관찰을 1분 간격의 계산으로 대체

> 차량 위치와 승객 상태를 1분 간격으로 기록합니다. 차량 수만 20대에서 10대로 바꿔 다시 계산하면 같은 수요와 도로망에서 두 운영안의 대기시간을 비교할 수 있습니다. 다만 비교 결과는 입력한 수요와 통행시간을 전제로 합니다. 호출 시각이나 통행시간이 실제와 다르면 대기시간도 달라집니다. 8장에서 수요를 만들고 9장에서 통행시간 모형을 점검합니다.

## 도구별 기본 단위와 적용 범위

표: 세 도구의 기본 단위와 분석에 적합한 질문
| 도구 | 기본 단위 | 공간 범위 | 적합한 질문 |
|---|---|---|---|
| VISSIM·AIMSUN (상용) | 차로 위 차량, 초 | 교차로~구역 | 신호 5초 증가 시 대기행렬 |
| SUMO (오픈소스) | 차로 위 차량, 초 | 구역~도시 | 위와 동일 + 파이썬 제어 |
| 이 책 (직접 작성) | 노드 위 차량, 분 | 도시 전체 | 차량 40대 감축 시 대기시간 |

- 도구 선택 기준: 분석할 질문과 필요한 해상도
- 미시 교통류 시뮬레이터: 차간거리·차로 변경을 시간 단위로 계산
- 상용 도구: 배차 과정을 직접 구현하는 실습에는 제약
- SUMO: TraCI로 실행 중 차량 제어, 수요응답 모의도 가능

> 교재의 VISSIM 화면을 함께 봅니다. 화면 전체가 교차로 하나이며 차량마다 차로 위의 위치를 계산합니다. 차량 움직임을 세밀하게 표현할수록 필요한 입력 자료와 계산량도 늘어납니다. SUMO도 이 수업의 분석에 사용할 수 있지만, 기본적으로 차로 위의 개별 차량 움직임을 계산하는 도구입니다.

## 수업에서 구현할 모형의 범위

- 계산에서 제외: 차로 안의 세부 차량 움직임
- 직접 기록: 분 단위 차량 위치
  - 수강생이 배차 규칙을 코드로 바꿔 다시 실행
- 활용 자료와 알고리즘
  - 도로망 OpenStreetMap (2장) · 최단경로 직접 구현 (3장) · 시간표 GTFS (5장)
- 직접 구현: 호출 발생, 배차, 차량 이동 처리

> 모든 구성요소를 새로 작성하는 것은 아닙니다. 공개 데이터와 표준을 활용하되, 호출 발생부터 배차와 차량 이동까지의 연결 과정은 직접 구현합니다. 이 구분은 한 학기 동안의 구현 범위를 보여 줍니다.

# 교재 1.3 시뮬레이션 결과 해석

## 평균이 가리는 대기시간 분포

표: 하남시 18:00–24:00, 택시 80대 시뮬레이션의 대기시간
| 지표 | 값 |
|---|---|
| 평균 대기시간 | 4.1분 |
| 50% 분위 | 3분 이내 |
| 상위 5% | 11분 초과 |
| 최대 대기시간 | 41분 |

- 호출 990건 전부 배차 (서비스율 1.0)
- 평균 대기시간 4.1분
- 평균만으로는 확인하기 어려운 41분 대기 사례

> 교재 1.3에서 sim.passengers의 대기시간 분위수를 직접 계산합니다. 평균만 보면 대부분의 승객이 비슷하게 기다린 것처럼 보이지만, 분포를 확인하면 장시간 대기 사례가 드러납니다. 이후 결과 분석에서도 평균과 분포를 함께 확인합니다.

## 차량 80대의 평균 운행 상태

- 승객 탑승 차량: 평균 10대
- 빈 차량: 평균 31대
- 비교 질문: 차량 40대일 때 평균 대기시간과 장시간 대기 승객 수
- 추가 확인: 990건 중 미배차 호출의 발생 여부

> 같은 저녁의 수요를 차량 40대로 다시 계산해야 두 운영안을 비교할 수 있습니다. 시뮬레이션에서는 차량 수를 나타내는 인자만 바꾸면 됩니다. 다만 교재 녹화본에는 80대 결과만 있으므로 40대로 실행하려면 DTUMOS 서버가 필요합니다. 11장에서는 직접 구현한 시뮬레이션 루프로 같은 질문을 분석합니다.

# 교재 1.4 시뮬레이터의 구조

## 시뮬레이터의 네 단계

![데이터 준비부터 결과 분석까지 시뮬레이터의 네 단계](figures/ch01_framework.png)

- 흐름: 데이터 준비 → 모형 보정 → 서비스 운영 → 결과 분석
- 서비스 운영 단계의 구성: 수요·차량 생성, 재배치, 배차, 차량 이동
- 각 구성요소와 교재의 장을 연결해 학기 진도 구성

> 배차 알고리즘에는 각 차량이 승객에게 도착하는 데 걸리는 시간이 필요합니다. 이 값을 예상 도착시간, 즉 ETA라고 합니다. 직선거리만 사용하면 강 건너 차량을 가장 가까운 차량으로 잘못 판단할 수 있습니다. 3장에서는 도로망 최단경로로 ETA를 계산하고, 9장에서는 통행 기록으로 학습한 모형을 사용합니다.

## 구성요소와 대응하는 장

표: 시뮬레이터의 각 구성요소와 그것을 다루는 장
| 구성요소 | 하는 일 | 장 |
|---|---|---|
| Data | 도로망·시간표·통행 기록 준비 | 2·5·8장 |
| Calibration · Vehicle Router | 통행시간 계산과 차량 위치 갱신 | 3~4·9장 |
| Demand & Supply Generator | 호출 시각·위치와 차량 수·초기 위치 | 8장 |
| Dispatch Algorithm | 호출 중복 시 차량 선택 | 10~11장 |
| Outputs | 대기시간·차량 상태 계산과 시각화 | 12장 |

> 매주 수업을 시작할 때 이 표에서 해당 구성요소를 확인합니다. 차량 재배치 알고리즘은 이번 학기 범위에 포함하지 않습니다. 빈 차량을 수요가 많은 지역으로 미리 이동시키는 문제로, 배차와 수요 예측을 함께 다뤄야 하기 때문입니다.

# 정리와 연습

## 1장 정리

- 시뮬레이터: 같은 하루를 조건만 바꿔 반복 실행하는 장치
  - 이 책은 차로 변경을 생략하고 호출 발생·배차·차량 이동을 직접 구현
- 평균과 분포를 함께 확인 — 평균 4.1분, 최댓값 41분
  - 80대 중 태운 차 평균 10대, 빈 차 31대
- 네 단계와 구성요소를 2장부터 12장까지 나누어 진행

> 학습 목표 네 가지에 답할 수 있는지 확인합니다. 시뮬레이터의 구성요소와 교재의 장을 연결한 뒤 다음 수업의 도로망 데이터로 이어갑니다.
