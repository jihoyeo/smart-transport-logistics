# 교재 3.1–3.2 문제와 아이디어

## 다익스트라의 근거

- 명제: 미확정 노드 중 최근접 노드의 현재 거리 = 최종 답
- 근거: 더 짧은 경로가 있다면 미확정 노드를 경유해야 함
  - 그 경유 노드는 현재 노드보다 멀리 있음
  - 엣지 비용이 음수가 아니므로 우회로 단축 불가
- 전제: 음수 비용 없음 — 소요시간에는 항상 성립

> 음수 비용이 있는 문제라면 다익스트라를 쓸 수 없고 벨만-포드를 쓴다. 통행료 환급 같은 경우다.

## 알고리즘 네 단계

- 1단계: 출발점 거리 0, 나머지 무한대
- 2단계: 미확정 노드 중 최소 거리 노드를 추출해 확정
- 3단계: 이웃마다 경유 시 단축 여부를 확인하고 갱신
- 4단계: 도착점을 추출하면 종료

> 2단계에서 매번 전체를 비교하면 느리다. 최소 힙을 쓰면 로그 시간에 끝난다. 같은 노드가 힙에 여러 번 들어갈 수 있어서 확정 집합으로 중복을 제외한다.

# 교재 3.3–3.4 구현과 검증

## 구현 결과

표: 하남시청에서 미사역까지 다익스트라 실행 결과
| 항목 | 값 |
|---|---|
| 소요시간 | 5.5분 |
| 경로에 쓰인 노드 | 83개 |
| 확정한 노드 | 4,500개 이상 |
| 전체 노드 대비 | 약 3분의 1 |

- 도로 4.2 km, 평균 시속 약 45 km
- 자유류 속도 기준 — 신호 대기 미반영
- 탐색이 목적지 방향이 아니라 전 방향으로 확장

> 마지막 줄이 중요하다. 83개짜리 경로를 얻으려고 4,500개를 확정했다. 이 손실이 A*의 출발점이 된다.

## 경로 연결 검증

- 검증 방법: 경로의 인접 노드 쌍마다 엣지 존재 확인
- 엣지 소요시간을 다시 합산해 알고리즘 결과와 비교
- 생략 시 경로 복원 배열의 오류를 발견하지 못함

> 2장의 검증 습관과 같다. 코드가 실행된다는 것과 결과가 맞다는 것은 별개다.

## NetworkX 대조

- 무작위 50쌍 대조 결과: 불일치 0건
- 부수 확인: 무작위 200쌍 중 경로 없음 6% 남짓
- 원인: 일방통행 막다른 구간, 시 경계에서 분리된 부분
- 시뮬레이터 요구사항: 경로 없음을 예외 처리

> 대조 과정에서 경로가 아예 없는 노드 쌍을 발견한다. 시뮬레이터가 이 경우를 처리하지 않으면 실행 중 예외가 발생한다.

# 교재 3.5 A* 확장

## 목적지 방향 우선 탐색

- 다익스트라의 손실: 목적지 반대 방향까지 균등 확장
- 개선: 남은 시간의 하한 h를 우선순위에 추가
- h = 직선거리 ÷ 도로망 최고 속도
- 우선순위 = 지금까지 소요시간 + h

> 정확한 남은 시간은 모르지만 하한은 안다. 도로는 직선보다 길고 최고 속도보다 빠를 수 없기 때문이다.

## 허용 가능 조건

- 조건: h가 실제 남은 시간보다 작거나 같을 것
- 용어: 이 조건을 허용 가능(admissible)하다고 함
- 위반 시 더 짧은 경로의 우선순위가 낮아져 최적해 상실
- 직선거리 ÷ 최고 속도는 항상 실제보다 작으므로 안전

> 결과는 다익스트라와 같고 확정 노드는 줄어든다. 연습 3.2에서 휴리스틱에 1.5를 곱해 이 조건이 깨졌을 때 무엇을 잃는지 직접 측정한다.

# 교재 3.6–3.7 성능과 엔진

## 확정 노드와 실행 시간

표: 무작위 30쌍의 중앙값 비교
| 항목 | 다익스트라 | A* |
|---|---|---|
| 확정 노드 | 기준 | 약 1.7배 적음 |
| 실행 시간 | 기준 | 더 김 |

- 원인: 노드 추출마다 하버사인 계산 — 삼각함수 4회
- 파이썬에서는 이 비용이 힙 연산보다 큼
- 언어와 규모의 문제 — C나 Rust에서는 A*가 유리
- 그래프가 커질수록 확정 노드 차이가 확대

> 이론적으로 더 좋은 알고리즘이 항상 더 빠른 것은 아니다. 무엇을 변경할 때마다 실행 시간을 측정하는 습관을 들인다.

## 실제 엔진의 축약 계층

- DTUMOS 라우팅 엔진은 A* 대신 축약 계층(Contraction Hierarchies) 사용
- 전처리: 중요도 낮은 노드 제거 후 대체 지름길 엣지 추가
- 질의: 양쪽에서 계층 위쪽만 탐색 — 확정 노드 수백 개 수준
- 비용 구조: 전처리 수 초에서 수 분, 질의 마이크로초

> 시뮬레이션은 같은 도로망에서 수십만 번 질의하므로 전처리 비용을 회수한다. 축약 계층을 직접 구현하지는 않고 필요할 때 HTTP로 호출한다. 4장에서 서버에 연결해 우리 구현과 대조한다.
